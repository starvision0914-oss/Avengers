## 문제
`/tmp/cron_cpc2.log`, `/tmp/cron_11st_cost.log` 등 다수 크론 로그가 **한 번도 로테이션/삭제
안 되고 몇 주씩(예: 6/18부터) 계속 append**됨. 게다가 로그 라인은 `[HH:MM:SS]` 형식으로
**날짜가 없어서**, 같은 파일 안에서 "이게 오늘 기록인지 지난주 기록인지" 구분이 안 됨.

## 실제로 겪은 혼란 (2026-07-06~07)
- 오전 25계정 로그인 실패를 "당일 7번 재실행됐다"로 오판할 뻔함 — 실제로는 여러 날의 기록이
  섞여 있었을 가능성. 파일 mtime과 내용의 타임스탬프가 안 맞아 보여서 헷갈림.
- 결론: 이런 로그 기반 "며칠 전 몇 시에 무슨 일이 있었나" 조사는 **날짜 확정이 안 되면 신뢰
  하지 말 것**. `event_time`/`GmarketAiAdHistory` 같은 **DB 기록이 진실**이고, raw 로그파일은
  참고용일 뿐.

**Why:** 로그만 보고 성급히 "N번 재실행됐다" 같은 결론 내리면 틀릴 수 있음(실제로 이 사건에서
정정한 적 있음).
**How to apply:** 시각 기반 원인조사는 가능하면 DB 테이블(History류, event_time 필드)을
우선 조회하고, 로그파일은 날짜 프리픽스가 있는지 먼저 확인 후 사용. 로그 로테이션 자체를
크론 스크립트에 추가하는 게 근본해결이지만 아직 안 함(개선 후보로 남겨둠).
