`crawlers/eleven_suspend_only.py`의 판매중지 액션은 "총 N건 중 N건 처리 완료" alert가 뜨면 실제로
성공한 것이 맞다. 다만 셀러오피스 "상품조회/수정" 탭의 라이브 카운트(판매중/품절/판매중지)와
`ElevenMyProduct.status_type`(엑셀 재수집 기준)에 반영되기까지 **몇 시간 단위의 처리 지연**이 있을 수
있다.

**Why:** 2026-09-04 rejoice999(아이리스) 계정에서 53배치·1,558건 판매중지 실행 직후(~15~40분 이내)
탭 카운트를 확인했더니 판매중지 27건(작업 전과 동일)으로 안 바뀐 것처럼 보여서 "자동화가 실제로는
작동 안 한다"고 잘못 결론 내렸었음. 약 3시간 뒤 다시 확인하니 판매중지 1,586건(27+1,558와 거의 일치,
품절은 2,294→734로 감소)으로 정상 반영돼 있었음 — 실행은 처음부터 성공했고 서버 처리 지연이었을 뿐.

**How to apply:** 판매중지 배치 실행 직후 몇십분 내에 라이브 카운트로 "실패"라고 성급하게 판단하지
말 것. 최소 1~2시간 이상 지난 뒤 재확인하거나, 실행 자체는 alert 파싱 결과(`applied_total`)를
신뢰하고 DB 동기화는 다음 정기 재수집(크론) 또는 하루 정도 지난 뒤의 수동 재수집으로 확인할 것.
`suspend_11st_confirmed_soldout.py`가 이미 `applied==requested`인 계정만 DB를 즉시 판매중지로
동기화하는 보수적 설계인 것도 이 지연 가능성을 감안한 것으로 보임 — 그 판단(완전성공 계정만 DB 갱신)은
유지하되, "라이브 카운트 불변=실패"라는 판단만은 성급했던 것.
