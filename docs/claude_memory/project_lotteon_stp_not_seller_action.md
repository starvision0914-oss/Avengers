롯데온에서 다른 플랫폼(11번가/지마켓/스마트스토어)과 동일한 "미매칭 전체 판매중지" 기능을 만들려고 실사이트(rejoice234 계정, store.lotteon.com)를 직접 로그인해 탐색한 결과(2026-08-23):

**핵심 발견:** 판매자센터 "상품 조회/수정" → 행 선택 → "상품판매 변경" → "상품정보일괄수정" 탭 → "일괄수정" 팝업에서 열리는 상태변경 드롭다운(`mf_spdSlStatCd`)의 선택지는 **"판매중" / "품절" / "판매종료" 3개뿐이고 "판매중지"는 아예 없음.**
좌측 메뉴의 별도 "판매중지 상품관리" 페이지에 직접 들어가보니 안내문에 명시: "법령/정책 위반 상품을 관리하는 메뉴입니다. 이 외의 다른 판매중지 사유는 CM을 통해 확인을 부탁드립니다." — **즉 판매중지(STP)는 롯데 측이 법령/정책 위반으로 강제 부여하는 상태이고, 판매자가 스스로 설정할 수 있는 액션이 아님.** 대시보드에 보이는 "판매중지 312건"은 셀러가 만든 게 아니라 롯데가 지정한 것.

**Why:** 사용자가 "롯데온 미매칭도 판매중지 만들어줘"라고 4개 플랫폼 통일을 요청했는데, 이 플랫폼은 구조적으로 동일한 개념의 셀프서비스 액션이 없음. 판매자가 실질적으로 쓸 수 있는 가장 가까운 등가 액션은 **품절(SOUT, 재고소진 — 되돌릴 수 있음)**이고, "판매종료"(END)는 UI에 "변경 시 이후 상태 변경 불가"라고 명시된 비가역 액션이라 후보에서 제외해야 함.

**추가로 확인한 UI 플로우(향후 구현시 재사용):**
- 로그인은 2FA 없이 폼입력(ID/PW)만으로 매번 성공함(이 세션 기준, 예상과 다르게 디바이스인증 불필요했음) — `crawlers/lotteon_product_crawler.py`의 `_login_and_get_token`이 "2FA 요구"로 실패한 건 별개 원인(동시 프로세스의 프로필 락 충돌 등)으로 추정, 재확인 필요
- 상품관리 진입: `mf_wfm_menuBox_gen_1stMenu_1_btn_1stMenu` → `mf_wfm_menuBox_gen_1stMenu_1_gen_2ndMenu_3_btn_2ndMenu`
- 행 체크박스: `[id*='grd_PdList___checkbox_check_N']`
- 상태변경 버튼: `input[value='상품판매 변경']` → 새 탭 "상품정보일괄수정"으로 이동(선택상품 자동 필터링됨)
- 일괄수정 버튼: `[id$='btn_btchMod']` → 팝업(iframe `[id$='cmNoPop_iframe']`) 안에 상태 드롭다운(`mf_spdSlStatCd_button`)과 확인/취소 버튼(`mf_btn_trigger1`=수정, `mf_btn_trigger11`=취소)
- **팝업 결과표에 판매자상품코드/판매자상품명/성공여부/실패사유 컬럼이 있어 클릭성공 여부를 실제로 검증 가능** — [[project_gmarket_suspend_success_not_sticking]]에서 발견된 "클릭성공=DB성공판정, 재조회검증없음" 버그를 반복하지 않을 수 있는 구조

**How to apply:** 다음에 이 기능 마저 만들 때는 (1) 사용자에게 목표상태를 "품절(SOUT)"로 할지 확인 먼저 받을 것 (2) 위 셀렉터로 `crawlers/lotteon_loss_delete.py` 작성, 반드시 팝업의 성공여부/실패사유 결과표를 파싱해 실제 성공만 DB 반영할 것 (3) 판매중지사유 체크박스(`sbx_...`, 목표상태를 품절로 하면 해당 없을 가능성 높음 — 확인 필요) 처리 로직 확인 필요.
